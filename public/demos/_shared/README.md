# Правило для кейсов (`public/demos/<case>/index.html`)

Каждый кейс — отдельная «вау»-витрина, и у каждого своя дизайн-система: Nova (светлый
поп-арт/Мемфис, Grandstander), Support Bot (тёплый редакторский, Fraunces, зелёный бренда
самого бота), Analytics Pulse (сдержанный дата-вайз). **Это осознанно, не баг** — портфолио
должно показывать диапазон, а не один шаблон с перекрашенными углами. Следующий кейс имеет
полное право на свой шрифт, свою палитру, свой motion-lens (restraint/polish/play).

Граница другая: **разное — это кожа. Одинаковое — это механика.**

## Что ОБЩЕЕ (бери из `_shared/motion.js`, не переизобретай)

- `MagneticCTA` — кнопка, тянущаяся к курсору
- `TiltCard` — карточка с 3D-наклоном за курсором
- `VelocityMarquee` — бегущая строка, реагирующая на скорость скролла
- `CountUp` — число, считающее вверх при попадании во вьюпорт
- `Reveal` — fade+slide-up при скролле

Это чистая механика (пружины, слушатели, IntersectionObserver) без единого цвета внутри.
Красишь через `className`/`style`/CSS-переменные снаружи. Нашёл баг в одном из них — чини
здесь один раз, а не в трёх файлах. Пример импорта (кейс — React/htm/Three.js, как Nova):

```js
import { MagneticCTA, TiltCard, CountUp, Reveal } from '../_shared/motion.js';
```

**Нашёл реальную причину завести ОБЩИЙ примитив:** если паттерн повторяется в 2+ кейсах
буквально (та же пружинная физика, тот же IntersectionObserver) — он механика, выноси сюда.
Если он выражает ИДЕЮ конкретного кейса (конфетти Nova, evidence-карточка прод-ботов
Support Bot, график Analytics Pulse) — он остаётся в файле кейса, даже если структурно
похож на что-то в другом кейсе.

## Что СВОЁ у каждого кейса (не выносить)

- OKLCH-токены (`--bg`, `--ink`, `--accent`...) и сама палитра
- Пара шрифтов (display + body) — у каждого кейса СВОЯ, не повторять с прошлого
- Motion-lens (пружинные константы `damping`/`stiffness`, передаваемые В общие примитивы —
  сами значения кейс выбирает сам, не примитив)
- Одна «незабываемая деталь» (3D-герой, конфетти, живой чат-виджет, график)

## Версии (важно — чтобы не разъезжалось)

`_shared/motion.js` тянет `react`, `react-dom`, `framer-motion`, `htm` через голые
спецификаторы — КАЖДЫЙ кейс-файл должен сам объявить их в своём `<script type="importmap">`
(статика, единого бандла нет). Пины, которые сейчас используются и должны совпадать
во всех кейсах, когда их касаешься:

```
react            → esm.sh/react@18.3.1
react/jsx-runtime→ esm.sh/react@18.3.1/jsx-runtime
react-dom        → esm.sh/react-dom@18.3.1
react-dom/client → esm.sh/react-dom@18.3.1/client
framer-motion    → esm.sh/framer-motion@11.11.17?external=react,react-dom
htm              → esm.sh/htm@3.1.1
```

(До выноса в `_shared/` версии framer-motion реально разъехались между Nova — 11.11.17 — и
Support Bot — 11.3.19 — просто от копипасты в разное время. Больше так не делаем.)

`three` и `animejs` — НЕ в этом списке: они нужны не всем кейсам (сейчас только Nova).
Кейс без 3D-героя их не подключает.

## Для чисто-вёрсточных кейсов без React (как Analytics Pulse)

Не обязаны участвовать в этой схеме вообще — `_shared/motion.js` завязан на React/htm.
Кейс на ваниле/SVG (дата-вайз, где `dataviz`-скилл и так диктует свою механику графиков) —
нормально остаться вне этой схемы. Не тащи React ради одной магнитной кнопки.

## Отдельно: наименование

`support-bot/` в корне репы — это Python/Telegram-бот (`bot/engine.py`...), отдельный
проект. `public/demos/support-bot/` — статичная кейс-страница портфолио. Один и тот же
корень имени, два разных назначения — при добавлении кейсов проверяй, не плодишь ли
аналогичную путаницу.
